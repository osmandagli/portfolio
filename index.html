L4 Transport · my master's thesis

Thesis

Accelerating a Media-over-QUIC Relay with AF_XDP Kernel-Bypass Networking

Osman Bugra Dagli · Politecnico di Milano · Jan 2025 – present · in progress

Media over QUIC (MoQ) is an emerging IETF protocol for live media delivery, and relays sit at its core. Every packet they forward passes through the kernel's network stack. This thesis measures how much that costs in Meta's moxygen relay and removes it.

A perf-based CPU-time breakdown shows that kernel packet I/O takes a significant share of each core's time. I built an AF_XDP zero-copy fast path and connected it to the QUIC stack through a non-invasive socket-injection seam, so the relay's entire UDP RX/TX path runs over AF_XDP with zero changes to the relay's source.

single-core RX throughput (Mpps, higher is better)

kernel · recvmmsg + GRO (tuned) ~0.65
AF_XDP · zero-copy ~1.55

~2.4× per core

  1. NIC
  2. driver · sk_buff
  3. UDP stack

after: kernel bypass

  1. NIC
  2. XDP redirect
  3. UMEM (zero-copy)
  4. AF_XDP socket
  5. injection seam
  6. QUIC
  7. relay

Contributions

  • A perf-based pipeline that breaks down per-core CPU time along the relay's data path
  • An AF_XDP zero-copy RX/TX path reaching ~1.55 Mpps on one core, against ~0.65 Mpps for a tuned kernel baseline (recvmmsg + GRO)
  • A socket-injection seam, built on proxygen's socket factory, that moves the relay onto AF_XDP without the relay knowing
  • A reproducible CloudLab testbed: one profile provisions the machines, applies the patch series to moxygen and proxygen, syncs clocks with PTP for one-way latency, and runs the fan-out, throughput and flame-graph experiments

Radiation-hardening Miosix

LLVM · STM32 · 2026

In orbit, a charged particle can flip a bit in a register or in RAM. That's a single-event upset, and the code keeps running on a wrong value. ASPIS is an LLVM plugin from Politecnico di Milano's HEAPLab that hardens code against this at the IR level. I integrated it into the build of Miosix, an embedded RTOS, so the kernel itself compiles hardened for an STM32F407.

Try it: click any bit of x to hit it with a cosmic ray. EDDI keeps a shadow copy of every value and compares the two before the value is used.

x 0x2A
x′ shadow 0x2A

icmp eq x, x′ is true, so execution continues.

  1. C / C++
  2. clangemits LLVM IR
  3. llvm-link
  4. ASPIS passesEDDI + CFCSS
  5. codegen
  6. .elf → .binobjcopy
  7. STM32F407
  • A CMake module that sends any target through the clang → opt → link pipeline and skips assembly files automatically
  • Every pass can be picked from the build script: data duplication (eddi, reddi, seddi, fdsc) and control-flow checking (cfcss, rasm, inter-rasm, racfed)
  • Compiled the whole kernel through ASPIS, then moved to selective hardening with annotations on the scheduler
  • A clang toolchain file that can point at any LLVM install, plus an objcopy step that produces a flashable .bin

containerrt

Go · Mar 2026

A minimal container runtime written from scratch on raw Linux primitives, with no runc and no libcontainer. I wanted to know exactly what docker run does before the process starts.

  1. clone()NEWUTS · NEWPID · NEWNS
  2. pivot_roothost root fully unmounted
  3. tmpfs /devessential device nodes
  4. cgroup v2limits applied by parent
  5. pipe barrierchild waits for setup
  6. exec
  • Isolation with UTS, PID and mount namespaces
  • pivot_root instead of chroot: the host root is unmounted, not just hidden
  • An ephemeral /dev tmpfs with only the essential device nodes
  • A pipe-based sync barrier between parent and child ensures the workload starts inside its cgroup v2 limits and can't race the setup
  • A real init: reaps zombies, forwards SIGINT/SIGTERM, and exits with the workload's code (128 + signal)
  • Tested with escape attempts, pids.current monitoring and OOM kills under memory.max

conntracker

eBPF/XDP · May 2025

Connection tracking and TCP fingerprinting that runs in the kernel at XDP, before the network stack ever allocates an sk_buff.

  • TCP and UDP state machines in eBPF, tracking per-connection metrics
  • Extracts TCP option sequences (MSS, SACK, timestamps, window scale) for OS and stack fingerprinting
  • A user-space daemon in C loads a YAML config, attaches the program, and serves stats and the ban list over HTTP
  • Count-Min sketch and Bloom filters for fast threshold-triggered filtering in bounded memory
